ENROLLMENT & ADMISSIONS PIPELINE - FRONTEND IMPLEMENTATION PLAN
===============================================================

Overview
--------
This plan outlines the frontend UI/UX approach to transition from a linear, tightly-coupled student-class architecture to the new "Enrollment Junction" architecture. This separates the CRM (Admissions) from the Active Academic Roster.

Phase 1: API Setup
------------------
[x] Add `ENROLLMENT` endpoints (`UNASSIGNED` and `BULK_ENROLL`) to `src/constants/apiEndpoints.js`.

Phase 2: The "Matchmaker" UI (Bulk Enrollment)
----------------------------------------------
Location: `src/pages/admin/Admin_Features/AcademicManagement/BulkEnrollment.jsx`
Action: Create a new Split-Screen / Dual-Listbox UI component to serve as the bridge between Admissions and Academics.

1. Left Column (The Admissions Pool):
   - Data Source: `GET /api/admin/enrollment/unassigned?academicYear=...`
   - Filters:
     - `Academic Year` (Required Dropdown - synced with right pane).
     - `Target Grade` (Optional Dropdown to filter applicants).
   - UI: Data table with Checkboxes for bulk selection.
   - Columns: Student Name, Applicant ID, Target Grade, Application Date.
   - Interactivity: "Select All" checkbox and a dynamic badge showing "[X] Students Selected".

2. Right Column (The Academic Destination):
   - Form Dropdowns: `Academic Year` (Synced), `Class/Grade`, `Section`.
   - Live Analytics: When a Section is selected, display a capacity badge (e.g., "Current Strength: 24/30").
   - Action: A prominent "Assign & Generate Roll Numbers" button.

3. Submission Workflow:
   - Client-side Validation: Ensure selected students count does not exceed available seats in the section.
   - Trigger `POST /api/admin/enrollment/bulk-enroll`.
   - On Success: Re-fetch the unassigned list (Left Column) and the updated capacity (Right Column). Trigger a success Toast.
